# Flag Learning Center

Phone-first web app that teaches our 5th-grade flag football offense: formations, routes, play calls, and how plays beat Cover 3, Cover 2 and Man. Built for the Lake Nona Rams.

**Live app:** https://notreallyacoder85.github.io/flag-learning-center/

Requirements: [docs/BRD.md](docs/BRD.md). Review list for the coach: [docs/REVIEW-CHECKLIST.md](docs/REVIEW-CHECKLIST.md). Visual/behavior reference: [docs/reference/prototype-v2.html](docs/reference/prototype-v2.html).

## Run it

```bash
npm install
npm run dev      # local dev server
npm test         # unit tests
npm run build    # production build into dist/
```

## Folder map

| Path | What lives there |
|---|---|
| `src/data/` | Coach-editable JSON: formations, routes, plays, settings. No code changes needed to edit these. |
| `src/engine/` | Pure logic with no DOM: call parsing, scene building, defenses, result evaluation. |
| `src/ui/` | Rendering and interaction. |
| `src/styles/` | CSS and bundled fonts. |
| `tests/` | Unit tests and the formation x defense x motion sweep. |
| `public/` | Icons, manifest, files copied as-is. |
| `scripts/` | `deploy.sh`, and `playbook-pdf/` (the tools that turned the coach's PDF into `playbook.json`). |
| `docs/` | BRD and reference prototype. |

## Editing the playbook

- Playbook plays (the Playbook tab) are in `src/data/playbook.json`: the coach's 2x2 Attack System plays. Each play has a formation, optional motion, and a drawn route for each receiver (`points` are lateral yards toward his own sideline, then yards deep). To change a route, edit its `points`. To add a play, copy an existing one and give it a new `id`.
- Draw Up's "More routes" (the Route Lab): the Specials and Double moves templates are in `src/data/routelab.json`. Each has a `stem` (yards straight up first, or null) and `steps` (moves after the stem). Stem and Break limits are in the same file.
- The 13 call-coded plays (like `Dubs 21129 Y Cross`) are in `src/data/callbook.json`. The call quiz, Read the defense and the concept cards use them.
- Tune a route: edit its `points` in `src/data/routes.json` (lateral yards, depth yards).
- Move a formation: edit `src/data/formations.json`.
- Quiz length and app name: `src/data/settings.json`.
- How far zone defenses lean toward the strong side (Trips, Quads, or motion that makes trips): `overload` in `src/data/settings.json` (`pxPerReceiver`, `maxPx`). Set both to 0 to turn it off.
- Wording of the tell and result callouts, and the quiz cheers: `src/data/copy.json`.
- Concept cards (Train tab): `src/data/concepts.json`. These are a first draft for the coach to edit.
- Route descriptions (shown after a route quiz answer): the `blurb` on each route in `src/data/routes.json`.
- Coach teaching points to keep in the app: [docs/COACH-NOTES.md](docs/COACH-NOTES.md).
- Ranks, XP per answer, and how hard Beat the Coverage is (`beat.thresholds`, in yards of separation): `src/data/settings.json`.

## Publishing changes

The site is served by GitHub Pages from the `gh-pages` branch. After you change something and commit it to `main`:

```bash
git push
npm run deploy     # runs the tests, builds, and publishes. Live in a minute or two.
```

`npm run deploy` refuses to run with uncommitted changes, so what is live always matches a commit.

Optional upgrade: automatic deploys on every push. That needs a GitHub Actions workflow file, and GitHub only lets a token push one after `gh auth refresh -s workflow` is run once. Until then, `npm run deploy` does the same job by hand.

## Wristband cards

The Wristband tab builds 4.25" x 2" cards of 6 plays (3 across, 2 down). Tap an empty slot to pick a play from the Playbook, My plays, or the play on the field. Tap a filled slot and then another slot to swap them (or drag one onto another). The Playbook also has an "Add to wristband" button. Cards are saved on this device, and you can keep several (for example one per opponent), each with an optional title line. Print puts the cards on a letter sheet at their true size: 5 per page upright, 8 per page sideways. Black and white is the default because it prints best. In the print dialog set Scale to 100% and turn off headers and footers.

## Enlarge the field

The expand button in the corner of the field (or the F key) opens the field full-window, with Play, the defense choices and the previous/next arrows. Esc or the close button goes back. It is available in the Playbook and in Draw Up.

## Install and offline

The built app is a PWA. After the first visit it works with no internet, and on a phone it can be added to the home screen (iPhone: Share, Add to Home Screen. Android: menu, Install app). The service worker is generated by `vite.config.js` on every build and lists every file, so there is nothing to maintain by hand. It only runs in the built app, not in `npm run dev`.

To test it: `npm run build && npm run preview`, open the page in Chrome, then stop the server and reload.
